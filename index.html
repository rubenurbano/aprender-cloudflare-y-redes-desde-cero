Internet Explicado desde Cero

Antes de configurar Cloudflare, debemos comprender con precisión quirúrgica qué es Internet, qué diferencia hay entre red y web, y qué ocurre exactamente cuando un usuario visita una dirección en su navegador.

Internet vs. La Web

Internet es la infraestructura física global de cables submarinos, routers, antenas y equipos interconectados. La Web es un servicio que corre sobre esa infraestructura: el conjunto de páginas y documentos hipertextuales accesibles mediante navegadores usando HTTP/HTTPS.

Cliente, Servidor y IP

El cliente (tu móvil o PC) solicita recursos. El servidor es un ordenador remoto siempre encendido que responde a esas peticiones. Cada dispositivo posee una dirección IP numérica (como 192.0.2.1 en IPv4 o formato IPv6) que funciona como la matrícula única en la red.

Práctica 1.1: Inspeccionar Peticiones de Red

  1. Abre tu navegador en el ordenador o móvil y entra a una página web.
  2. Pulsa F12 para abrir las Herramientas de Desarrollador.
  3. Selecciona la pestaña Network (Red).
  4. Recarga la página (Ctrl + R). Observa cómo cada recurso (HTML, imágenes, scripts) genera una petición independiente con su código de estado HTTP (200 OK, 404 Not Found, etc.).

DNS: La Agenda de Contactos de Internet

El Sistema de Nombres de Dominio (DNS) traduce nombres legibles como ejemplo.com a direcciones IP numéricas. Sin él, tendríamos que memorizar números IP para cada servicio web.

Tipo Función Principal Ejemplo de Uso
AAsocia un dominio a una dirección IPv4.ejemplo.com → 203.0.113.10
AAAAAsocia un dominio a una dirección IPv6.ejemplo.com → 2001:db8::1
CNAMECrea un alias apuntando un nombre a otro dominio.www → ejemplo.com
MXDefine los servidores de correo electrónico del dominio.10 mail.proveedor.com
TXTAlmacena texto libre para verificación y seguridad (SPF, DKIM, DMARC)."v=spf1 include..."
NSIndica qué servidores de nombres autoritativos gestionan la zona.ns.cloudflare.com

Práctica 2.1: Consultar Registros DNS por Terminal

Abre PowerShell (Windows) o tu terminal WSL/Linux y ejecuta las siguientes consultas de diagnóstico:

# Consultar registros IP asociados a un dominio
nslookup example.com

# Consultar nameservers usando el resolutor público global 1.1.1.1 de Cloudflare
nslookup -type=ns example.com 1.1.1.1

Cloudflare: Qué es y Cómo Funciona el Proxy Inverso

Cloudflare opera como una inmensa red perimetral (Edge Network) distribuida por todo el planeta con tecnología Anycast. Se sitúa entre tus visitantes y tu servidor de origen para acelerar la entrega y bloquear amenazas en el perímetro.

Nube Naranja (Proxied)

El tráfico web pasa por los servidores de Cloudflare. Se activa la protección DDoS, caché global, reglas de seguridad WAF y optimización SSL/TLS. El visitante no ve la IP real de tu servidor.

Nube Gris (DNS Only)

Cloudflare responde únicamente a las peticiones DNS devolviendo la IP directa de tu servidor de origen. Es obligatorio para registros de correo (MX) y servicios que no admiten proxy web.

Modos de Cifrado SSL/TLS

  • Off / Flexible: Cifrado parcial entre usuario y Cloudflare, pero sin cifrar entre Cloudflare y el origen (no recomendado).
  • Full / Full (Strict): Cifrado extremo a extremo. Full (Strict) valida obligatoriamente que el certificado SSL del servidor de origen sea legítimo y de confianza (puedes usar certificados gratuitos Cloudflare Origin CA).

Publicar Sitios Web Estáticos y Cloudflare Workers

Cloudflare Workers permite ejecutar código JavaScript, TypeScript o Python directamente en su red global perimetral sin gestionar servidores tradicionales. Las peticiones a archivos estáticos en Workers son completamente gratuitas e ilimitadas.

Práctica 6.1: Crear y Desplegar una Web con Wrangler CLI

Asegúrate de tener Node.js instalado en tu terminal y ejecuta los comandos oficiales de inicialización de Cloudflare:

# 1. Verificar versión de Node.js
node --version

# 2. Inicializar un proyecto de sitio estático con C3
npm create cloudflare@latest -- mi-primera-web
# Responde: Hello World example -> Static site -> TypeScript/JavaScript -> No deploy aún

# 3. Entrar a la carpeta y probar en local (http://localhost:8787)
cd mi-primera-web
npx wrangler dev

# 4. Desplegar a producción en red global workers.dev
npx wrangler deploy

Seguridad Web Esencial y WAF

El Firewall de Aplicaciones Web (WAF) de Cloudflare protege tus propiedades digitales analizando cada petición HTTP en tiempo real mediante reglas gestionadas y reglas personalizadas definidas por el usuario.

Reglas Gestionadas

Conjuntos de reglas predefinidos por expertos de Cloudflare para bloquear ataques OWASP Top 10 e inyecciones comunes.

Reglas Personalizadas

Filtros personalizados basados en expresiones (país, IP, ruta, cabeceras) para bloquear o desafiar tráfico malicioso.

Rate Limiting

Limita automáticamente el número de peticiones por segundo desde una misma IP para mitigar ataques de fuerza bruta.

Práctica 7.1: Crear una Regla WAF de Bloqueo

  1. Entra a tu panel de Cloudflare, selecciona tu dominio y ve a Security → WAF → Custom rules.
  2. Pulsa Create rule e introduce un nombre descriptivo (ej: bloquear-prueba).
  3. Define la condición: URI Path equals /prueba-bloqueo.
  4. Acción: Selecciona Block y guarda los cambios para ver el desafío activo.

Rendimiento, CDN y Estrategias de Caché

Cloudflare almacena contenido estático en centros de datos cercanos geográficamente a tus visitantes. Por defecto, Cloudflare cachea extensiones estáticas (imágenes, CSS, JS) y respeta las cabeceras Cache-Control del origen.

Comprobación de Estado de Caché (cf-cache-status)

Puedes comprobar si una respuesta se sirvió desde la red perimetral analizando las cabeceras HTTP devueltas:

  • HIT: El archivo se sirvió directamente desde la caché de Cloudflare.
  • MISS: El archivo no estaba en caché y se solicitó al servidor de origen.
  • DYNAMIC: El contenido no es cacheable por defecto (como HTML dinámico).

Automatización y API de Cloudflare

Toda la gestión de Cloudflare se puede automatizar mediante su API REST utilizando tokens de acceso con permisos granulares de principio de menor privilegio, evitando el uso de claves globales de cuenta.

Verificar Token de API mediante Terminal

curl "https://api.cloudflare.com/client/v4/user/tokens/verify" \
  --header "Authorization: Bearer TU_TOKEN_API"

Diagnóstico y Resolución de Errores HTTP 5xx

Cuando una web detrás de Cloudflare experimenta fallos, los códigos de error HTTP de Cloudflare (520 a 526) indican exactamente dónde se rompió la comunicación entre la red perimetral y tu servidor de origen.

Código Significado Técnico Causa Habitual y Solución
520Respuesta vacía o inesperada del servidor.El origen devolvió datos corrompidos o sin formato HTTP válido.
521El servidor de origen rechaza la conexión.El servidor web está apagado o bloquea las IPs de Cloudflare en su firewall.
522Tiempo de espera agotado (Connection timed out).El origen tarda demasiado en responder o está saturado de tráfico.
524Tiempo de espera de aplicación agotado (~120s).El script del servidor tardó más de dos minutos en procesar la petición.
526Certificado SSL inválido en el origen.El certificado SSL instalado en tu servidor ha caducado o no es válido.

Errores Frecuentes y Trampas Clásicas

Evita los tropiezos más comunes al configurar dominios, nameservers, registros y despliegues con Cloudflare.

1. Cambiar los Nameservers sin comprobar los registros de correo (MX/TXT)

Si activas Cloudflare olvidando copiar los registros MX o SPF/DKIM de tu anterior proveedor, el correo electrónico del dominio dejará de recibirse inmediatamente.

2. Activar Proxy (Nube Naranja) en registros que no son HTTP

Los registros de correo y subdominios FTP o SSH no deben pasar por el proxy web de Cloudflare; deben permanecer en nube gris (DNS only).

3. Olvidar desactivar DNSSEC en el registrador antes del cambio

Si tu registrador anterior tenía DNSSEC activo, cambiar los nameservers sin desactivarlo previamente provocará que el dominio sea inaccesible globalmente.

Glosario de Términos y Fuentes Oficiales

Definición clara de todos los conceptos técnicos empleados y referencias a la documentación oficial consultada.

Glosario Esencial

  • Anycast: Técnica de encaminamiento donde múltiples servidores comparten una misma dirección IP.
  • CDN: Red de distribución de contenido optimizada geográficamente.
  • DNS: Sistema de nombres que traduce dominios a IPs.
  • Proxy Inverso: Intermediario situado frente a los servidores de origen.
